# LKS-SDD v0.6.0 — definición guiada y diseño visual

**Fecha:** 2026-08-20

**Canal:** release candidate técnica

**Hitos:** M0–M5 conservados; evolución compatible de definición y UX; M6 no ejecutado

## Changelog

La relación de cambios está en la entrada `0.6.0` de `CHANGELOG.md`. Esta versión corrige la deriva del comportamiento conversacional ya contratado y añade una extensión canónica para snapshots de cobertura y diseño/prototipado visual.

## Capacidades incluidas

- Encuadre inicial que evita presuponer dominio, usuarios o producto ante una idea ambigua.
- Tandas de una a tres preguntas de alto impacto, con opciones neutrales cuando ayudan a decidir.
- Snapshots comprensibles de información suficiente, parcial, desconocida, no aplicable y bloqueada.
- Especificación condicional con detalle y estados por pantalla, flujos enlazados, interacción, dirección visual y accesibilidad.
- Ciclo visual obligatorio para frontend nuevo o cambio material cuando existe brief suficiente e ImageGen está disponible: una a tres propuestas, validación humana, persistencia PNG/JPG y trazabilidad por SHA-256.
- Reutilización documentada mediante `Visual mode=reuse`, activo confirmado, motivo y ADR compartida cuando el incremento conserva la experiencia.
- Revisión manual en navegador 1.1 ligada por hashes al árbol de fuentes de implementación, `ART-INCREMENTS`, `ART-UX`, `VIS-###`, viewports y capturas exactos.
- Fallback explícito cuando ImageGen no está disponible, sin archivos ni validaciones inventados.

## Perfiles y locks

El perfil H0 continúa siendo `WEB-FASTAPI-REACT-KEYCLOAK-PG` con su `technology-profile.yaml` y `technology-profile.lock.json` versionados. Esta release no modifica sus versiones bloqueadas ni lo convierte en pila seleccionada u homologada automáticamente.

## Validación y evals

La puerta `candidate` ejecuta el validador oficial del plugin, contrato y hashes canónicos, perfil H0, pruebas, evals deterministas, integridad de fixtures, gate técnico completo y regresión contra `quality/baselines/v0.4.0.json`.

Ejecución local del 2026-08-20: `candidate=passed`, perfil Docker completo superado, suite de 80 casos unitarios completada sin fallos (79 ejecutados y un `skipped`), cinco evals deterministas superadas, cero fallos críticos y regresión `passed`. La única prueba omitida fue el caso de symlink que Windows no permite crear sin el privilegio correspondiente; el validador mantiene el rechazo y el caso queda visible como `skipped`, no como ejecutado.

FX-01 pasa de una evidencia automatizada incorrecta a evaluación semántica. FX-20 cubre el snapshot de definición y FX-21 el ciclo visual. El corpus y la rúbrica están versionados, pero sus sesiones no se han ejecutado: el canal `definition-conversation` permanece `not-run`. También permanecen pendientes los demás canales semánticos, humanos y de piloto que no dispongan de observaciones reales.

## Vulnerabilidades conocidas y limitaciones

- No se conocen vulnerabilidades confirmadas introducidas por esta evolución; esta declaración no sustituye una revisión de seguridad.
- Una imagen generada puede contener texto impreciso, inconsistencias o sesgos y no demuestra accesibilidad, responsive ni comportamiento.
- La disponibilidad de ImageGen depende de la superficie activa; su ausencia se declara y puede bloquear el alcance visual afectado.
- No existe soporte equivalente verificado en ChatGPT Work, Copilot, Claude u otros asistentes.
- No se ha ejecutado el piloto M5, M6 ni una evaluación semántica/humana de los nuevos escenarios.
- La baseline, el perfil H0 y esta release mantienen estado `candidate`; no existe aprobación como política corporativa.

## Actualización desde 0.5.0

1. Revisar `CHANGELOG.md`, esta nota y `docs/V0.6-DEFINITION-UX-COVERAGE.md`.
2. Verificar el bundle, manifiesto y `SHA256SUMS` del commit etiquetado cuando exista publicación autorizada.
3. Sustituir la candidate instalada mediante el flujo controlado de marketplace; no actualizar desde este repositorio de forma automática.
4. Abrir una tarea nueva de Codex y confirmar que siguen visibles exactamente las seis skills.
5. Validar cada proyecto consumidor antes de continuar su definición.

## Migración

No se requiere migración automática: no cambian `method_version`, `schema_version` ni los campos obligatorios existentes. Los nuevos bloques de UX se incorporan gradualmente solo cuando son aplicables y preservando las ediciones humanas.

Un proyecto con frontend puede ampliar `ART-UX` y añadir activos bajo `docs/lks-sdd/03-solution/ui-prototypes/`. Su ausencia no invalida retroactivamente una baseline 0.5.0; sí puede quedar como pendiente para un incremento 0.6.0 con cambio visual material.

## Rollback

La distribución puede volver a la candidate `0.5.0` usando su etiqueta y checksum inmutables. El rollback del plugin no revierte automáticamente Markdown, imágenes o código de proyectos consumidores; esos cambios se revisan y revierten por separado, conservando evidencia y ediciones humanas.

## Soporte

GitHub Issues continúa reservado a incidencias no sensibles y saneadas. Vulnerabilidades, datos personales, secretos o contenido de cliente se comunican únicamente por el canal confidencial externo asignado antes de cualquier piloto. No existe SLA aprobado.

## Responsables

El propietario del método, mantenedores, responsable de UX, revisión de accesibilidad, seguridad, publicación y soporte nominales siguen pendientes de designación externa. Esta release no inventa sus identidades ni interpreta la generación o los tests como aprobación.

## Estado de release

`0.6.0` puede cerrarse como candidate técnica si supera sus puertas automatizables. No puede publicarse como `stable` mientras `definition-conversation`, activación, revisión documental o piloto requeridos permanezcan `not-run`, incompletos o fallidos.
