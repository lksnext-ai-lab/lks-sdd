# Cobertura 0.14: verificación incremental y continuidad Jira

## Estado contractual

LKS-SDD 0.14.2 conserva `method_version: 1.5.0`, `schema_version: 1.5` y compatibilidad de proyectos 1.0–1.5. No modifica `specs/canonical/` ni requiere migrar un proyecto consumidor. La evolución pública queda limitada a evidencia de entrega G4 1.1, compatible en lectura con evidencia completa 1.0.

## Cobertura de aceptación

| Área | Implementación | Regresión automatizada |
|---|---|---|
| Slice backend en incremento con interfaz | `_visual_applicability` y `_binding_ids_for_tasks` | backend no aplicable con razón; solo `BIND-001` |
| Frontend, mixto y release conjunta | señales TASK UX/VIS/capability/unit/profile y scope de release | gate visual aplicable; frontend sin evidencia sigue `not-verified` |
| Build reproducible | `lks-sdd-build-1.0` y JSON canónico | estabilidad ante duración, PID, logs, Compose y orden; mutaciones reales cambian ID |
| G3 → G4 | `--materialize-delivery-template`, evidencia 1.1 `draft/complete` | dos ejecuciones reproducen build; divergencias de revisión, árbol, build o artefacto fallan cerrado |
| CKPT | frontmatter YAML y tabla de identidad parseados | generado/consumido inmediato; comillas equivalentes; TASK/EXEC ajenas rechazadas |
| PROB/Jira | alias compatible `issues` → `problems` | bloqueo crea PROB abierto consumible; cerrado, ajeno o inexistente rechazado |
| Portabilidad | paths normalizados y rutas canónicas | separadores Windows/POSIX producen la misma identidad |
| Identidad EVID 1.2 | contrato compartido de binding/perfil/versión/lock/build | proyecto multiperfil con slice de un binding genera pareja superior exacta; multiperfil nuevo omite el resumen |
| Validación autoconsumible | candidato validado antes de escribir y validadores posteriores sobre el estado materializado | G3 → G4 → record → validate-project → traceability TASK pasa sin excepciones de consumidor |
| Atomicidad semántica | rollback de EVID, ART-TRACE y manifest completo ante cualquier rechazo posterior | evidencia sintéticamente inválida restaura verification, last_delivery, evidence_ids y EXEC |

Los tests no acceden a un proyecto consumidor real. Construyen workspaces mínimos bajo directorios temporales y llaman exclusivamente al código del plugin.

EVID mantiene schema 1.2: las evidencias heredadas se leen sin mutación cuando su identidad puede reconstruirse sin ambigüedad. Las evidencias nuevas de un solo binding incluyen `profile_id`/`profile_version`; las nuevas multiperfil omiten ambos campos superiores y conservan el conjunto exacto en las estructuras detalladas.

## Evidencia y límites

`build_id` no contiene resultados ni metadatos de ejecución. `verification_run_id` identifica aparte la corrida y `checks` conserva duración y diagnósticos observados. Una plantilla G4 no es evidencia superada: `draft`, `pending`, `not-run` y ausencia nunca cuentan como `passed`.

Los tests Jira son offline y verifican intenciones, markers y recibos locales. No acreditan interoperabilidad Jira/Rovo real. Los canales humanos, semánticos y de piloto conservan su estado real.
