# Adoptar o migrar en v3

Distinga sistema sin SDD de proyecto v2. Sin SDD, adopt-inspect lee únicamente las fuentes indicadas; separe hechos, inferencias y pendientes y confirme intención. Configure mediante init y registre adopt con cobertura parcial. Para v2, lea la guía de migración v3 solo cuando proceda. migration-diagnose no modifica nada. migration-preview fija orígenes, identidades, configuración y conservación; aplique la vista concreta tras la decisión de conversión. Compruebe migration-continuation. No regenere planes heredados ni renueve autoridad histórica por cambiar encabezados. No convierta consumidores solo porque se actualizó el plugin.

Use `python -B <plugin-root>/scripts/lks_sdd.py v3 ACCION <proyecto> --input <datos.json>`.
Los datos se preparan a partir de documentos y decisiones observados. `--apply`
materializa una operación ya autorizada; no pida permiso por cada registro local.
Para revisar un cambio todavía no autorizado, guarde su paquete con `--output`.
La [referencia de operaciones](../../../docs/V3-OPERATIONS.md) se consulta solo para
los campos concretos que necesite preparar, no se carga íntegra por defecto.

`migration-preview` prepara ahora el destino 3.1 desde v2 o 3.0 y actualiza un
runtime 3.1 anterior. Incluya colaboración, personas confirmadas y runtime_bundle,
también sin lock. Consulte [la migración](../../../docs/V3-MIGRATION.md) solo para
preparar este corte; no renueve autoridad histórica ni regenere planes equivalentes.

Para una decisión nueva, use [la guía común](../../../docs/USER-DECISIONS.md),
consulte `decision-view` y presente su contenido. Conserve el receipt y páselo como
`presented` con la respuesta explícita; no solicite otra firma por registrar.
Lea únicamente el recurso que corresponda:

- Al preparar adopción o migración: [project-setup](../../../docs/decision-guides/project-setup.md).
- Al recuperar una operación: [exceptions-continuity](../../../docs/decision-guides/exceptions-continuity.md).

Si cambia el evento, cargue sus condiciones; tras compactación relea las fuentes
necesarias. La vista de decisión no sustituye el contrato de implementación.

## Diagnóstico para mejorar el plugin

Conserva observaciones de preparación/adopción y bloqueos previos; una inspección no prueba intención confirmada ni lectura del host. Reutiliza run_id tras compactación/relevo y declara huecos. Lee [la guía de diagnóstico](../../../docs/USAGE-FEEDBACK.md) solo al conservar o exportar el caso. No crees checkpoints por consulta ni atribuyas ahorro sin medición.
