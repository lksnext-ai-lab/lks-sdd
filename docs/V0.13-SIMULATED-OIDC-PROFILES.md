# Cobertura de perfiles OIDC simulados en LKS-SDD 0.13.0

## Alcance y decisión

La versión 0.13.0 añade `CAP-IDENTITY-OIDC-SIMULATED` y dos perfiles exactos para desarrollo, CI, integración y aceptación-preproducción:

- `API-FASTAPI-SIMULATED-OIDC-PG-OCI`;
- `WEB-REACT-VITE-SIMULATED-OIDC-STATIC`.

Son bindings desplegables independientes. No forman un perfil de sistema implícito y no se componen dinámicamente. Su identidad, usuarios, tenant, claves y tokens son sintéticos. `external_interoperability` es `not-applicable`: la certificación no acredita interoperabilidad con un proveedor externo ni, en particular, con Microsoft Entra.

## Contrato de seguridad no productivo

Ambos perfiles fallan cerrados si el entorno no pertenece a la allowlist no productiva. El perfil API rechaza `APP_ENV=production`; el perfil SPA rechaza `VITE_APP_ENV=production`. También exigen un issuer bajo `/__test__/oidc`, permiten HTTP únicamente en loopback y requieren HTTPS para un host remoto de aceptación-preproducción. No pueden satisfacer un binding productivo ni sustituir el requisito productivo de Microsoft Entra.

El API incluye discovery, JWKS, clave RSA efímera al arrancar, tokens RS256, Authorization Code con códigos de un solo uso y PKCE S256. Valida issuer, audience, tenant, expiración y scope o role; utiliza identificadores sintéticos estables; y produce respuestas 400, 401 y 403 deterministas. El gate integrado recorre authorize, token y endpoint protegido con PostgreSQL, Alembic y la imagen OCI.

La SPA usa React, Vite y TypeScript con un adaptador provider-neutral, Web Crypto para PKCE S256 y un intercambio authorize/token en dos pasos. No usa MSAL, client secret ni `localStorage`; tokens y sesión quedan limitados a `sessionStorage`. Sus gates cubren lock, lint, tipos, tests, build, salida estática, browser smoke, accesibilidad, PKCE, sesión, seguridad y composición.

## Certificación y FX-54

`FX-54` exige simultáneamente que los dos perfiles resuelvan `automation_support: supported`, tengan locks vigentes y certificación exacta completa, con `external_interoperability: not-applicable`. Cualquier cambio en descriptor, capabilities, driver, scaffold, gates, composición o motor de certificación invalida la evidencia y obliga a regenerar lock y certificación.

El lifecycle solo puede ser `active` mientras esa evidencia exacta permanezca válida. Los perfiles `API-FASTAPI-ENTRA-PG-OCI` y `WEB-REACT-VITE-ENTRA-STATIC` continúan `candidate`, `unsupported` y con interoperabilidad Microsoft Entra real `not-run`; no se introduce fallback, equivalencia ni afirmación de compatibilidad real.

## Límites

La release sigue siendo candidate, skills-only y no acredita M6, canal stable, piloto humano, política corporativa aprobada, Microsoft Entra real ni Rovo/Jira real. La identidad simulada es una herramienta controlada de desarrollo, no una implementación de producción.
