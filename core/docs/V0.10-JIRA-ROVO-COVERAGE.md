# Cobertura 0.10 — tracking operativo con Jira y Rovo

## Estado

La versión 0.10.0 implementa como candidate la propuesta 1.4 de tracking operacional. Mantiene las siete fuentes canónicas intactas y versiona la extensión en `specs/proposed/`; no presenta esa propuesta como política corporativa aprobada.

## Autoridad

| Estado o dato | Autoridad |
|---|---|
| alcance, requisitos, aceptación y TASK | Markdown LKS-SDD |
| dependencias, planificación y huellas | Markdown LKS-SDD |
| AUTH, EXEC, CKPT y evidencia | Markdown LKS-SDD |
| binding `external_id`, key, URL y estado remoto observado | Jira observado, registrado de forma saneada |
| assignee, sprint y tablero | Jira sólo si una política posterior los autoriza; fuera del contrato automatizado actual |

Jira `Done` nunca crea una transición local `done`. El estado externo es un hecho operativo observado, no una prueba de implementación o verificación.

## Frontera de integración

LKS-SDD prepara intenciones y registra recibos. Atlassian Rovo es un peer opcional instalado, conectado y autorizado por separado. El manifiesto no incluye MCP, cliente Jira, apps, hooks, agentes ni una dependencia dura no validada.

La 0.10.0 automatiza únicamente las operaciones que exponen sus comandos exactos. Transiciones, comentarios, adjuntos, mapping de workflows y otras acciones no demostradas permanecen fail-closed. Un timeout o resultado incierto exige búsqueda y reconciliación antes de reintentar.

## Calidad y canales

- `automated`, `fixture-integrity`, `profile-complete` y `regression` siguen siendo obligatorios para candidate.
- `definition-conversation`, `activation`, `document-review` y `pilot` siguen opcionales para candidate y obligatorios para stable.
- El corpus 0.10 añade selección de modo, autoridad y degradación, pero su ejecución humana continúa `not-run`.
- La interoperabilidad con una instancia Jira real mediante Rovo pertenece al piloto; no se infiere de mocks, fixtures o recibos sintéticos.

## Riesgos controlados

- duplicación tras timeout: marcador estable, búsqueda y reconciliación;
- cambio de key: identidad por `external_id`;
- deriva semántica: conflicto/PCH, nunca importación silenciosa;
- caída externa: eje degradado separado de planificación y autorización;
- exposición: campos cerrados, datos sintéticos y ausencia de credenciales;
- falsa evidencia: Jira no puede cerrar gates ni crear `EVID-###`.
