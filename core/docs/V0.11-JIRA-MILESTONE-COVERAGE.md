# Cobertura v0.11 — reporting Jira por hitos

## Estado

La versión 0.11.0 implementa como candidate la propuesta 1.5 sin modificar las siete fuentes canónicas. La experiencia `repository-only` permanece completa. Jira y Atlassian Rovo son opcionales; la interoperabilidad real sigue `not-run` hasta un piloto autorizado.

## Límites demostrados

- Jira nunca modifica por sí solo TASK, AUTH, EXEC, CKPT, EVID, dependencias o decisiones.
- Los eventos se limitan a inicio, progreso significativo, bloqueo, reanudación, revisión y verificación.
- `done` exige evidencia local `verified`; un status remoto no la sustituye.
- Los comentarios excluyen logs, chat, secretos, PII, rutas absolutas y worklogs.
- `advisory` permite continuidad local ante degradación; `required-before-execution` solo aplica el gate previamente confirmado.
- No se soportan adjuntos, asignación automática, worklogs, borrado, archivado, Jira-only, Data Center, webhooks ni sincronización bidireccional.

## Calidad y rendimiento

El ciclo de desarrollo usa `scripts/run_fast_validation.py` para contratos y pruebas focalizadas. No genera evidencia de release. El harness candidate sigue ejecutando la suite integral desde un checkout limpio. Su canal de perfiles puede usar `--profile-mode reuse` cuando todas las certificaciones exactas están vigentes y sus hashes siguen concordando; `--profile-mode execute` conserva la recertificación Docker completa para deriva, caducidad o petición explícita.
