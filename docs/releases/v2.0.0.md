# LKS-SDD v2.0.0

**Fecha:** 2026-09-18. Release técnica estable; contrato consumidor 2.0 y método 2.0.0.

## Changelog

La versión 2 reorganiza el trabajo alrededor de especificaciones para personas,
funcionalidades con identidad e historia y tareas con autoridad y evidencia propias.
Véase el [changelog](../../CHANGELOG.md) y el [índice de documentación](../V2-INDEX.md).

- Consultas documentales integradas con fuentes abribles, sin modificar el contrato.
  Ampliación al código ante carencia concreta o petición expresa; admite SDD parcial.
- Catálogo ligero, relaciones padre/hija lógicas, evolución y sustitución parcial o
  total, división/fusión y descomposición de solicitudes extensas sin duplicar TASK.
- Markdown humano con identidad estable, enlaces validados e historia recuperable.
- Contexto literal de ejecución, planificación completa o incremental explícita,
  autorización vigente por alcance/entorno, diff real y continuidad reconciliada.
- Evidencia tipada e inmutable; componente, integración, persistencia, visual,
  aceptación humana y entrega no se confunden. Verificación proporcional y
  variantes tecnológicas aprobables en el proyecto, sin certificación global.
- Migración oficial 1.5 → 2.0, originales conservados y rollback protegido.
- Seis skills revisadas, núcleo compartido Codex/Copilot y runtime fijado por proyecto.

## Compatibilidad

El contrato 2.0 no es intercambiable con 1.5. Se conserva el workflow 1.5 para
consumidores sin migrar; actualizar el plugin personal no cambia el runtime del
proyecto. Consultar la [matriz de compatibilidad](../COMPATIBILITY.md).

Los paquetes tienen adaptadores Codex desktop y GitHub Copilot VS Code Agent.
Su paridad automática no prueba aceptación conversacional. No se declara soporte
universal de versiones/modelos, edición concurrente distribuida, Claude, ChatGPT
Work ni extensión Codex de VS Code.

## Perfiles y locks

Se conservan el catálogo, perfiles active/candidate, locks y certificaciones exactas.
El gate de release comprueba vigencia y coherencia de todos los perfiles active;
no certifica nuevas combinaciones por similitud ni promociona candidates. Microsoft
Entra y las interoperabilidades externas sin evidencia permanecen unsupported/not-run.
Una variante aprobada tiene alcance, entorno, vigencia y observers propios; nunca
dispensa un gate crítico ni equivale a certificación global.

## Validación y evals

El asset `quality-report.json` de esta release es la evidencia técnica del commit
exacto, con inventarios, resultados, omisiones y comparación con baseline. Los
assets se generan dos veces desde ese commit y deben coincidir byte a byte;
`release-manifest.json`, `distribution-manifest.json` y `SHA256SUMS` enlazan el conjunto.

El [informe de implementación](../validation/v2-implementation.md) conserva la
campaña previa: 544 pruebas pasadas, una omitida por privilegios Windows, ensayos
Docker reales, migración/rollback con núcleo completo y consulta fijada p95 de
1,340 s para 100 documentos y 4,750 s para 1.000 (20 consultas por tamaño). Es
evidencia de desarrollo histórica, no sustituto del reporte limpio de publicación.

La [aprobación específica v2](../../quality/release-approval-v2.0.0.json) autoriza
publicar si pasan los gates técnicos. Comprensión humana, conversaciones reales
Codex/Copilot, navegación, piloto de equipo, coste total del agente e interoperabilidad
Rovo/Jira o Entra siguen `not-run` cuando no hay evidencia. No se hereda aceptación 1.x.

## Vulnerabilidades conocidas y limitaciones

No se afirma ausencia de vulnerabilidades ni auditoría exhaustiva de seguridad.
Roles declarados no autentican personas; hashes no son firma del editor. El guard
local detecta incumplimientos desde una base confiable, pero no intercepta todas
las escrituras del host. No hay coordinación remota ni locks distribuidos.
Las transacciones son recuperables mediante journal, no atómicas globalmente.
Ver [guardrails y límites](../V2-GUARDRAILS.md).

## Actualización

V2 requiere las dependencias Python fijadas en `requirements-runtime.txt`, además
de Python 3.11+. Prepararlas explícitamente en un entorno de herramientas separado;
el setup no instala paquetes ni obtiene red automáticamente. Sin `jsonschema` no
se omite la validación. La guía incluye instalación con hashes y vía sin red usando
un wheelhouse autorizado.

Seguir la [guía de instalación](../INSTALLATION.md) y verificar los checksums.
Copilot usa el catálogo con `copilot-v2.0.0`, etiqueta separada del árbol generado;
Codex dispone del marketplace y setup. No activar plugin nativo y skills de proyecto
simultáneamente. Publicar los assets no instala ni activa el plugin en ningún equipo.

## Migración

Solo se soporta 1.5/1.5.0 → 2.0/2.0.0 mediante
[diagnóstico, preview y autorización](../V2-MIGRATION.md). Se preservan originales,
EVID y activos. Reconciliar límites de funcionalidades, identidad, aplicabilidad,
TASK, bindings, gobierno y autoridad antes de implementar. No inventar historial.

## Rollback

Conservar el paquete anterior verificado para una instalación personal. En el
consumidor, usar el recibo exacto y detenerse ante trabajo posterior; no borrar
evidencia, mover etiquetas ni revivir autorizaciones antiguas. Retirar el plugin
no revierte automáticamente el contrato o código del proyecto.
