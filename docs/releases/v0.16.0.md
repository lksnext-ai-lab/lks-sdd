# LKS-SDD v0.16.0

**Fecha:** 2026-08-29

## Resumen

0.16.0 es una release minor compatible que convierte la evidencia de validación por TASK en una salida clara y gestionable sin añadir un proceso manual. Sobre las capacidades 0.15 existentes, cierra el contrato visual 1.2, genera fichas derivadas en `work verify`, separa historial y salud actual, corrige `current_task`, limita Jira a hitos relevantes y conserva reuse/rollback.

## Changelog

Véanse `CHANGELOG.md` y `docs/V0.16-VALIDATION-EVIDENCE.md` para el detalle diferencial, schemas, implementación, regresiones y benchmark.

## Compatibilidad y migración

No cambia el método 1.5.0 ni el schema de proyecto 1.5. Mantiene lectura de proyectos y EVID 0.15, no reescribe evidencia y no cambia fingerprints por fichas derivadas. Las revisiones visuales históricas 1.1 siguen legibles; las nuevas usan 1.2. Véase `docs/MIGRATION-0.16.0.md`.

## Validación de release

La puerta candidate exige contrato del plugin, integridad de fixtures, tests por tiers, evals deterministas, perfiles completos, benchmark 0.15→0.16, doble build reproducible, instalación limpia aislada y validación del bundle extraído. Los resultados exactos se fijan en `quality-report.json`, `release-manifest.json` y `SHA256SUMS` del artefacto.

Los canales semánticos, humanos, piloto, Microsoft Entra real y Rovo/Jira real no se infieren de las pruebas automatizadas y permanecen `not-run` salvo evidencia externa posterior.

## Perfiles y locks

No cambia ningún descriptor, driver, scaffold ni lock de perfil. Los perfiles active conservan su certificación exacta; los candidates y sus límites no se promueven por esta release.

## Validación y evals

Se exige el harness candidate completo, FX-56 a FX-60, fixture genérico, benchmark 0.15→0.16, doble build reproducible, instalación limpia aislada y validación integral del ZIP extraído.

## Seguridad y límites

No se incorporan MCP, conectores, hooks, apps, credenciales ni agentes ejecutables. Jira continúa como proyección y un resultado `failed`, `blocked`, `not-run`, `not-verified` o `verified-with-reservations` nunca solicita transición a Done.

## Vulnerabilidades conocidas y limitaciones

No se conocen vulnerabilidades nuevas derivadas del cambio. Las revisiones humanas, el piloto y la interoperabilidad externa permanecen fuera de la attestación automatizada.

## Actualización

Verifique `SHA256SUMS` y `release-manifest.json`, retire la versión anterior mediante el flujo soportado de Codex e instale el bundle 0.16.0. Abra una tarea nueva o reinicie la aplicación para cargar la versión; no edite la caché manualmente.

## Migración

No hay migración de proyecto. Siga `docs/MIGRATION-0.16.0.md`; conserve las EVID y revisiones 1.1 históricas y use visual review 1.2 únicamente para verificaciones nuevas.

## Rollback

El rollback técnico temporal del runtime vuelve a 0.15.0 sin reescribir datos del proyecto. El rollback transaccional de cada materialización restaura EVID, traza, manifest y fichas derivadas como una unidad.

## Soporte

La versión continúa como candidate técnica. Una publicación no implica soporte corporativo estable ni aprobación formal del método.

## Responsables

Los responsables corporativos siguen pendientes y no se inventan en esta release.
