# LKS-SDD v0.15.0

**Fecha:** 2026-08-29

## Changelog

Esta release unifica la ejecución de calidad por tiers, selección dirigida por cambios, telemetría, fail-fast y presupuestos bloqueantes con una experiencia de proyecto más ligera: vistas management/developer/audit, fast path de tarea, problemas vigentes, doctor rápido, parser compartido, evidencia 1.2 compatible y reutilización por sujeto técnico.

Véanse `CHANGELOG.md`, `docs/V0.15-QUALITY-EFFICIENCY-COVERAGE.md` y `docs/V0.15-PRODUCT-EXPERIENCE.md`.

## Compatibilidad

- No cambia el método 1.5.0 ni el schema de proyecto 1.5. Es el único contrato de proyecto soportado; los schemas 1.0–1.4 y el comando de migración dejan de distribuirse.
- Un índice 1.5 puede conservar `plugin_version: 0.12.0` como procedencia de materialización. El runtime 0.15.0 se informa por separado y no reescribe ese dato.
- El CLI histórico `python tests/run_unit_tests.py` sigue ejecutando todo. Los nuevos argumentos `--suite`, `--module`, `--test` y `--json-out` son aditivos.
- Los quality reports 1.1 siguen siendo validables como evidencia histórica. No pueden acreditar ni empaquetar una release 0.15.0, que requiere un reporte 1.2 del mismo commit, fecha y versión.
- No se reescriben proyectos consumidores, evidencias G4, CKPT, PROB, mappings ni recibos Jira.

## Perfiles y locks

Los perfiles active deben conservar certificaciones exactas vigentes o recertificarse si cambian descriptor, driver, scaffold, locks o motor. Los perfiles Entra continúan candidate y `unsupported`; la interoperabilidad real Microsoft Entra permanece `not-run`.

## Validación y evals

- Registro de suites completo y sin duplicados.
- Tres ejecuciones limpias comparables quedan como requisito para fijar la baseline temporal del commit de release; no se atribuyen al árbol de desarrollo.
- Evals deterministas, contrato del plugin, estructura y certificaciones exactas de perfiles.
- Doble build byte a byte reproducible, instalación limpia del ZIP y verificación de scripts, skills, schemas y perfiles.
- Revisión de que el diff y el paquete no contienen proyectos consumidores, caches, `site/` ni `docs/LKS-SDD-SITE-STORYBOARD.md`.
- Evals de comprensión management, lifecycle de problemas, autorización no repetida, bloqueo de producción no aplicable, matriz de mutaciones y presupuesto de 13 tareas/420 relaciones.

Los resultados exactos, commit y checksums de la puerta publicable forman parte de `quality-report.json`, `release-manifest.json` y `SHA256SUMS`, vinculados al tag `v0.15.0`. Los canales semánticos, humanos y de piloto, incluida la interoperabilidad Rovo/Jira real, no se declaran ejecutados por las pruebas automatizadas.

## Vulnerabilidades conocidas y limitaciones

No se conocen vulnerabilidades nuevas derivadas de este cambio. La baseline temporal comparable debe completarse con tres ejecuciones limpias del commit de release; hasta entonces los límites absolutos siguen bloqueando. Responsables corporativos, soporte estable, piloto real y aprobaciones metodológicas continúan pendientes.

## Actualización

Verifique `SHA256SUMS` y `release-manifest.json`, retire la versión anterior mediante el flujo soportado de Codex e instale el ZIP de marketplace 0.15.0 desde su release autorizada. Reinicie o abra una tarea nueva para cargar la versión; una tarea ya abierta no cambia de plugin en caliente.

## Migración

No hay migración de proyecto. `method_version: 1.5.0` y `schema_version: 1.5` no cambian. Un contrato anterior se rechaza sin escritura. El quality report 1.1 se conserva solo como evidencia histórica y no se reescribe.

## Rollback

Durante la adopción de la única instalación existente, el rollback técnico puede volver a 0.14.2 usando su bundle y checksums publicados. No se deshacen ni reescriben datos del proyecto consumidor. Este puente termina al estabilizar 1.0; el rollback transaccional de una operación fallida sí permanece como garantía de atomicidad.

## Soporte

La versión continúa como candidate técnica. Una publicación en GitHub no implica soporte corporativo estable ni aprobación del método.

## Responsables

Los responsables corporativos siguen pendientes y no se inventan en esta release.
