# Aclaraciones, tecnología y dirección visual

Para una aclaración, explique qué falta y por qué importa; ofrezca alternativas
reales y las consecuencias de aplazar. Mantenga las tandas breves y adaptativas.
Una respuesta ambigua o «no lo sé» conserva un pendiente. Si es crítico para la
porción, no invente la decisión ni amplíe permisos; el trabajo independiente puede
continuar con cobertura explícita.

Una elección técnica presenta necesidad, alternativas, recomendación, componentes
y contratos afectados, consecuencias/comprobación y pendientes. Compare desde
requisitos y restricciones, con costes o licencias conocidos identificados y los
desconocidos explícitos. La tecnología propuesta no se presenta como observada.
Puede integrarse en la solución de [especificaciones](specifications.md).

Una dirección visual muestra pantallas y estados, imágenes reales, diferencias y
recomendación, alcance de selección y pendientes. No sustituya imágenes por nombres
de archivo: obsérvelas y muéstrelas al usuario. Confirme disponibilidad y huella
de los assets. `observed_assets` declara las imágenes efectivamente observadas y sus
huellas; nunca rellene ese dato sin observación. Una selección visual no aprueba
funcionalidad nueva ni acredita accesibilidad o implementación.

Estas presentaciones son consultas; no incorporan un generador ni una API nueva.
Las guías históricas no habilitan sus comandos en v3. Use los medios realmente
disponibles y autorizados; conserve como pendientes la generación o transferencia
que no se hayan realizado. Los Markdown gobiernan comportamiento y texto; una
imagen validada gobierna solo la dirección y composición acordadas. Ante conflicto,
exponga la diferencia y no elija silenciosamente una interpretación.
