# Implementar y corregir en v3

Con colaboración integral 3.1, consulte interventions/readiness y reutilice la
revisión del encargo que ya cubra el plan aprobado. Si falta, agrupe la revisión
del técnico con recepción e inicio; nunca firme por el compañero. Continúe las
transiciones técnicas autorizadas sin preguntar por cada registro de avance.

Identifique al operador, tarea y autorización vigente. Cargue context de la porción con todas sus obligaciones literales, adjuntos y reglas globales; no use una síntesis humana como contrato. Revise readiness y registre start o resume antes de código. Preserve cambios ajenos y trabaje dentro del alcance asignado; use handoff para una ayuda parcial y su aceptación por el destinatario. Ejecute pruebas y controles declarados. analysis importa un informe con procedencia y sujeto exactos; analysis-run usa únicamente el ejecutor y argumentos previamente autorizados. Corrija dentro del encargo, vincule hallazgos con checkpoint y repita las comprobaciones afectadas. Un alcance nuevo vuelve a propuesta/plan. Registre implement al terminar código; verificación y cierre son pasos distintos. Checkpoints solo en hitos, bloqueos o relevos útiles. No ejecute Sonar por cada comando. No uso acordado, no aplicabilidad, error y análisis superado son estados distintos.

Use `python -B <plugin-root>/scripts/lks_sdd.py v3 ACCION <proyecto> --input <datos.json>`.
Los datos se preparan a partir de documentos y decisiones observados. `--apply`
materializa una operación ya autorizada; no pida permiso por cada registro local.
Para revisar un cambio todavía no autorizado, guarde su paquete con `--output`.
La [referencia de operaciones](../../../docs/V3-OPERATIONS.md) se consulta solo para
los campos concretos que necesite preparar, no se carga íntegra por defecto.

Para una decisión nueva, use [la guía común](../../../docs/USER-DECISIONS.md),
consulte `decision-view` y presente su contenido. Conserve el receipt y páselo como
`presented` con la respuesta explícita; no solicite otra firma por registrar.
Lea únicamente el recurso que corresponda:

- Al revisar o recibir el encargo: [assignments](../../../docs/decision-guides/assignments.md).
- Al valorar una excepción o cambio de continuidad: [exceptions-continuity](../../../docs/decision-guides/exceptions-continuity.md).
- Al ejecutar o revisar controles: [verification](../../../docs/decision-guides/verification.md).
- Al delimitar una corrección: [corrections](../../../docs/decision-guides/corrections.md).

Si cambia el evento, cargue sus condiciones; tras compactación relea las fuentes
necesarias. La vista de decisión no sustituye el contrato de implementación.
