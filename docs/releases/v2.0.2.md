# LKS-SDD v2.0.2

**Fecha:** 2026-09-18. Release técnica estable del plugin; contrato consumidor
2.0 y método 2.0.0 sin cambios.

## Changelog

- Normaliza raíces de instalación y proyectos con Windows extended-length paths
  (`\\?\` y `\\?\UNC\`) únicamente en la capa filesystem.
- Expande alias 8.3 solo para comparar identidades de runtime; no persiste esos
  nombres ni prefijos en mappings, recibos, hashes, manifests o mensajes de negocio.
- Conserva las comprobaciones de symlinks, junctions/reparse points, escapes,
  `.git`, repositorios anidados, rutas sensibles y secretos.
- Si el sistema no puede resolver una ruta por `MAX_PATH`, devuelve un diagnóstico
  explícito con una solución accionable en lugar de afirmar que falta un fichero.

## Compatibilidad

El plugin 2.0.2 conserva `schema_version: 2.0` y `method_version: 2.0.0`.
La compatibilidad de lectura 1.5 permanece separada de la migración explícita:
actualizar el plugin no sustituye el runtime fijado ni modifica consumidores.

## Perfiles y locks

Se mantienen los perfiles active/candidate, sus locks y certificaciones exactas.
La actualización del plugin no sustituye el runtime fijado de un consumidor ni
promociona combinaciones candidate por similitud tecnológica.

## Validación y evals

`tests/test_windows_long_paths.py` instala el plugin en una ruta superior a 260
caracteres y compara contra una ruta corta:

- validación contractual y validación de perfiles;
- verificación completa de cada registro de `package-integrity.json`;
- `v2 migration-diagnose` y `v2 migration-preview --target-runtime`;
- hash y writes del preview idénticos;
- proyecto consumidor sin modificaciones durante el preview.

En sistemas que no son Windows el caso queda omitido explícitamente; no se presenta
como evidencia ejecutada de soporte Windows.

## Vulnerabilidades conocidas y limitaciones

Los hashes no son firmas del editor, los roles declarados no autentican personas,
las transacciones no son atómicas globalmente y no existen locks distribuidos.
La migración no verifica código consumidor ni operaciones externas.

## Actualización

Se mantienen `schema_version: 2.0`, `method_version: 2.0.0`, la compatibilidad de
lectura 1.5 y la migración explícita con autorización. Actualizar el plugin no
migra consumidores ni sustituye su runtime fijado.

Para Copilot usa la etiqueta `copilot-v2.0.2`; verifica los SHA-256 publicados y
mantén el runtime histórico del consumidor hasta completar su migración autorizada.

## Migración

Solo se soporta 1.5/1.5.0 → 2.0/2.0.0 mediante diagnóstico, preview y
autorización del hash exacto. Se conservan originales, evidencias, identidades,
relaciones y runtime histórico; las TASK con semántica pendiente requieren
reconciliación antes de continuar.

## Rollback

Conserva el paquete 2.0.0 verificado para una retirada explícita. En consumidores,
usa el recibo exacto y detente ante trabajo posterior; no muevas etiquetas ni
reactives autorizaciones históricas.

## Soporte

Release técnica sin nuevo SLA. Para incidencias, usa los canales de soporte,
seguridad y gobierno sin adjuntar credenciales ni datos de consumidores.

## Responsables

El responsable del proyecto autoriza esta publicación condicionada a los gates
técnicos. Mantenimiento, aceptación de producto y activación personal siguen
siendo responsabilidades separadas.

La release no afirma aceptación conversacional de Codex/Copilot, piloto,
interoperabilidad externa ni instalación activa.
