# LKS-SDD v1.1.1

**Fecha:** 2026-09-11. Corrección estable de distribución para Codex desktop y GitHub Copilot en VS Code.

## Changelog

La distribución compacta únicamente los nombres de ruta de la evidencia de
certificación dentro de los paquetes. Conserva los bytes observados, sus SHA-256
completos y las comprobaciones de tamaño, por lo que el checkout Git que utiliza
Copilot evita rutas demasiado largas sin reescribir la evidencia fuente del
repositorio. Los paquetes Codex y Copilot contienen el mismo núcleo compacto.
Véase [CHANGELOG](../../CHANGELOG.md).

## Compatibilidad

No cambia el schema consumidor 1.5 ni el método 1.5.0. Codex desktop y el plugin
GitHub Copilot para VS Code mantienen sus seis skills, runtime fijado por proyecto,
setup explícito y relevo visual existente. El presupuesto se valida para la caché
estándar de VS Code en Windows; una ubicación manual con un prefijo excepcionalmente
largo puede seguir necesitando un destino más corto.

## Perfiles y locks

Se conservan 23 perfiles: 17 `active` con certificaciones exactas y 6 `candidate`
sin promoción. La proyección de distribución no modifica descriptores, locks ni
fuentes de certificación del repositorio; verifica antes de empaquetar los hashes y
tamaños de los artefactos activos.

## Validación y evals

La aprobación propia `quality/release-approval-v1.1.1.json` registra la autorización
del responsable para publicar esta corrección, condicionada a los gates técnicos del
commit exacto. El asset `quality-report.json` de la release acredita esos gates por
separado. La publicación requiere checkout limpio, doble build reproducible,
validación de los ZIP de Codex y Copilot, manifiestos y `SHA256SUMS`.
El límite interno de cada módulo `fast` se calibra a 90 s tras medir 60,191 s para
el shard de experiencia limpio; el límite bloqueante global de 120 s y las
aserciones de rendimiento del producto no cambian.
La ruta de release ejecuta el harness integral una sola vez: ya contiene los cuatro
tiers, los evals y la atestación exacta inicial de fuente. Se eliminan las
ejecuciones previas redundantes, mientras que cada tier conserva su presupuesto
bloqueante interno y el techo externo de 900 s sólo protege la recuperación de
diagnóstico y limpieza de un despachador bloqueado.
La comprobación de portabilidad mantiene un clon con `core.autocrlf` y los hashes
de todos los artefactos contractuales afectados, pero usa una fixture Git exacta
en vez de duplicar el checkout completo que el harness ya valida por separado.

## Vulnerabilidades conocidas y limitaciones

SHA-256 detecta corrupción, pero no firma al editor. No existe evidencia nueva de un
piloto de tres desarrolladores, de todos los recorridos conversacionales ni de
interoperabilidad real Rovo/Jira; esos canales siguen `not-run`. Las políticas
corporativas y las rutas de caché redirigidas de forma inusual pueden impedir una
instalación aunque el paquete respete el presupuesto de ruta estándar.

## Actualización

Sigue la [instalación paso a paso](../INSTALLATION.md). En Copilot usa el catálogo
`https://github.com/lksnext-ai-lab/lks-sdd.git`, que fija la etiqueta inmutable
`copilot-v1.1.1`; en Codex usa el marketplace ZIP de esta release. Actualizar el
plugin personal no cambia automáticamente el runtime del proyecto: ejecuta su setup,
revisa la vista previa y versiona sólo los cambios autorizados.

## Migración

No hay migración del contrato consumidor. El setup nativo conserva los adaptadores
gestionados y no duplica skills ni sobrescribe personalizaciones. Cierra o reconcilia
los relevos visuales pendientes antes de cambiar el runtime.

## Rollback

Retira sólo archivos gestionados con el instalador y prepara el paquete 1.1.0
verificado si fuera necesario. Conserva documentos, imágenes, decisiones y evidencias
del consumidor; no muevas ni reutilices etiquetas publicadas.

## Soporte

Se cubren Codex desktop y el plugin Copilot en VS Code dentro de los límites
documentados. No se establece un SLA corporativo. Informa versión, digest, comando y
diagnóstico saneado, sin credenciales ni chats.

## Responsables

La aprobación corresponde al rol responsable del proyecto y se registra sin
identidades. No se asignan responsables de soporte corporativo no confirmados.
