# Entrevista de descubrimiento

## Objetivo

Convertir una idea inicial en un encuadre verificable sin imponerle un producto genérico. Una palabra como «calculadora», «portal», «gestor» o «dashboard» describe como mucho una forma posible; no demuestra el dominio profesional, el problema ni las reglas que debe resolver.

## Base mínima del encuadre

Antes de confirmar el brief o derivar funciones, descubrir progresivamente:

1. **Dominio y contexto profesional:** ámbito, situación de uso y proceso actual.
2. **Usuario:** perfil que realiza la tarea y otros perfiles afectados.
3. **Tarea, proceso o decisión:** qué necesita hacer, decidir o demostrar la persona.
4. **Entradas y reglas:** datos de entrada, unidades, fórmulas o reglas, excepciones y fuente autorizada.
5. **Resultado:** salida esperada, uso posterior, medida de éxito y consecuencias de un error.

Una dimensión puede permanecer `unknown` o `partial`; no rellenarla con prácticas habituales ni con la opción aparentemente más probable.

## Tandas adaptativas

- Formular de una a tres preguntas por tanda, empezando por las que más cambian el producto.
- Ofrecer opciones solo cuando ayuden a pensar. Etiquetarlas como `Propuesta A`, `Propuesta B`, etc.; incluir siempre `Otra` y `No lo sé todavía`.
- Hacer opciones específicas al contexto disponible, no una taxonomía cerrada. La opción seleccionada sigue necesitando una respuesta inequívoca antes de registrarse como hecho, requisito o decisión.
- Explicar en una frase por qué importa cada pregunta y qué parte de la definición desbloquea.
- Tras cada respuesta, actualizar solo lo confirmado, recalcular las dimensiones afectadas y decidir la siguiente tanda. No repetir información ya aportada.
- Permitir diferir, cerrar el nivel de detalle para un alcance concreto o registrar un riesgo residual.

## Primer encuadre de una idea ambigua

La primera tanda debería cubrir normalmente tres ejes diferentes:

1. el dominio o proceso donde se usará;
2. quién la usa y qué tarea o decisión necesita resolver;
3. qué entradas, reglas o resultado distinguen una respuesta válida de una incorrecta.

Ejemplo para «quiero una calculadora»: preguntar si se trata de una utilidad general, un cálculo profesional regulado, una pieza de un proceso existente u otro contexto; después descubrir usuario y decisión; finalmente preguntar por entradas, fuente de fórmulas, unidades, redondeos, trazabilidad y consecuencias de error según resulten aplicables. Estas opciones son propuestas para aclarar, no características confirmadas.

En la primera respuesta, priorizar esta tanda y una explicación breve; no desplegar todavía el mapa completo de cobertura salvo que la persona lo solicite. Mostrar el snapshot compacto cuando las respuestas hayan permitido actualizar el encuadre o cerrar un bloque, evitando que el estado vacío eclipse las preguntas iniciales.

## Escritura segura

Si la persona autoriza inicializar antes de completar el encuadre, mantener los apartados como `open` y conservar `OPEN-001`. No escribir «aplicación genérica», no seleccionar pila, no inventar pantallas y no convertir ejemplos ofrecidos en requisitos.

El encuadre concluye para un alcance cuando la persona puede reconocer en el resumen el dominio, usuario, tarea o decisión, reglas o fuentes pendientes y resultado esperado. Esto no equivale a que toda la especificación esté completa.
